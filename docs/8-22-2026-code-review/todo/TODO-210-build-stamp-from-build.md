# TODO-210 — Generate the build stamp at build time (`__BUILD__`), move it out of the `<h1>`, expose it in `<meta>`

**Priority:** P1   **Effort:** S   **Theme:** C — presentation/platform/maintainability
**Source findings:** 03-presentation-ui-ux-review.md § 1 V-6, § Prioritised fix list #20; 05-expansion § QW-16; 06-architecture § 8.1 "No build stamp", F-12
**Depends on:** none   **Blocks:** TODO-215 (SW cache version), TODO-238 (`/api/health` reports build), TODO-213 (CI asserts stamp present)

## Why
`b59` is a hand-edited string inside the product name (`<h1>単語帳 <span class="tc-build">b59</span></h1>`). It is stale by construction (nothing bumps it), sits in the brand block where a build number doesn't belong, and cannot be used for anything (cache-busting, support, health checks). esbuild can inject the git SHA + timestamp in one line.

## Current behaviour (verified)
- `JpnFlashcards.jsx:1459` `<h1 className="tc-wordmark">単語帳 <span className="tc-build">b59</span></h1>`; `.tc-build` CSS L5872.
- `tools/build.mjs:31-42` esbuild options: `entryPoints, bundle, minify, format:"iife", jsx:"automatic", loader, nodePaths, write:false` — no `define`, no `target`.
- `index.html` head (L1-12) has no `<meta name="build">`; `cf/src/index.js` has no notion of a build id.
- The Browse › More panel (L3992-4026) is the natural home for diagnostics.

## Intended behaviour
- `tools/build.mjs` computes `BUILD = "<yyyymmdd-HHMM>-<shortsha>[-dirty]"` and passes `define: { __BUILD__: JSON.stringify(BUILD) }`; it also writes `<meta name="build" content="…">` into the head of `index.html` (replacing any previous one) and `cf/public/build.txt`.
- The JSX reads `__BUILD__` (with a `typeof` guard for tests), shows it only in Browse › More as "Build 20260822-2130-7b9e110" (copyable), and the `<h1>` is just `単語帳`.
- The Worker can read the stamp from `cf/public/build.txt` via `env.ASSETS` (used by TODO-238).

## Implementation steps
1. `tools/build.mjs` — after the imports add:
   ```js
   import { execSync } from "node:child_process";
   const sh = (c) => { try { return execSync(c, { cwd: ROOT, stdio: ["ignore", "pipe", "ignore"] }).toString().trim(); } catch { return ""; } };
   const sha = sh("git rev-parse --short HEAD") || "nogit";
   const dirty = sh("git status --porcelain -- JpnFlashcards.jsx data tools cf/src") ? "-dirty" : "";
   const stamp = new Date().toISOString().replace(/[-:T]/g, "").slice(0, 13).replace(/(\d{8})(\d{4})/, "$1-$2"); // 20260822-2130
   const BUILD = process.env.TANGOCHO_BUILD || `${stamp}-${sha}${dirty}`;
   ```
   and in the `build({...})` options add `define: { __BUILD__: JSON.stringify(BUILD) }, target: ["es2020", "safari14", "chrome90"],`.
   **Reproducibility note:** the timestamp makes two builds of the same commit differ. For the CI drift check (TODO-211/213) the check must compare with the stamp neutralised, or CI must set `TANGOCHO_BUILD=ci-${GITHUB_SHA::7}` *and* the committed artifact must be built the same way. Recommended: make the default stamp `git-<sha>[-dirty]` **without** the time component (deterministic), and add the time only to `cf/public/build.txt`. Decide and document in `tools/build.mjs` header.
2. Head meta: after computing `out`, replace/insert the meta:
   ```js
   const META = `<meta name="build" content="${BUILD}">`;
   const withMeta = out.includes('<meta name="build"') ? out.replace(/<meta name="build" content="[^"]*">/, META) : out.replace("<title>", META + "\n<title>");
   fs.writeFileSync(HTML, withMeta, "utf8"); // and the cf/public copy
   fs.writeFileSync(path.join(CF_PUBLIC, "build.txt"), BUILD + "\n");
   ```
   Note the splice logic (`open`/`close` L66-79) uses `orig` = the committed `index.html` as template; because the meta lives in the head, it is preserved and rewritten each build.
3. JSX: near the top (after L16) add `const BUILD_ID = typeof __BUILD__ !== "undefined" ? __BUILD__ : "dev";`. Change L1459 to `<h1 className="tc-wordmark"><span lang="ja">単語帳</span></h1>`. In Browse › More (L3992+) add `<p className="tc-buildline">Build {BUILD_ID} · <button className="tc-linkbtn" onClick={() => navigator.clipboard?.writeText(BUILD_ID)}>copy</button></p>` with `.tc-buildline{font-size:11.5px;color:var(--mut-2);margin:8px 0 0;}`. Delete `.tc-build` (L5872) if unused.
4. Rebuild; commit `tools/build.mjs`, `JpnFlashcards.jsx`, `index.html`.

## Data migration / compatibility
none. `cf/public/` is gitignored; `build.txt` is generated by the build like `index.html`/`videos.json`.

- Local server → Browse › More shows "Build …"; `<h1>` text is exactly `単語帳`; `document.querySelector('meta[name=build]').content` matches.

## Pitfalls / notes
- esbuild `define` replaces the identifier textually; never write `window.__BUILD__` — use the bare identifier with the `typeof` guard (which esbuild also folds).
- `git` must be on PATH where the build runs (CI has it; the fallback is `"nogit"`).
- Rebuild + commit `index.html`; `cd cf && npx wrangler deploy`.
